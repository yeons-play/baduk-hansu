### 강의 단계 종류
`explain` 설명 · `tap` 점 누르기 · `liberties` 숨구멍 찾기 · `choice` 고르기(정답 `libs`·`area`·`total`·`more`·`turn`·`legal`은 엔진 계산) · `free` 하양이와 번갈아 놓기 · `move` 흑돌 직접 놓기(`goal`: `capture`·`atari`·`escape`·`connect`·`cut`·`live`) · `find` 단수인 하양이 돌 찾기 · `territory` 까망이 집 찾기.
보조 칸: `as: 'w'`(하양이 차례로 묻기), `setup.moves`(되따기 금지처럼 이전 판 기억), `showOwner`(집 네모 표시). 자리표시 `{libs}` `{area}` `{warea}` `{stones}` `{total}`.

## 3. 작업 흐름 (꼭 지킬 것)

1. `main`에서 새 가지를 만들어 작업 → 커밋 → push → PR 생성
2. **PR 합치기(merge)는 사용자(연쓰)가 GitHub에서 직접** 누른다. 작업 환경의 안전장치가 검토 없는 merge와 저장소 설정 변경을 막는다. 합치기 전 마지막 확인 기회이기도 하다.
3. 합친 뒤 배포까지 2~3분 걸린다. 배포 상태는 Actions 탭 "배포 (GitHub Pages)"에서 확인
4. 사용자는 개발 용어에 익숙하지 않다. PR·merge 같은 말은 "결재해서 원본에 반영"처럼 쉽게 설명

### `gh` 사용 시
- GitHub GraphQL이 막혀 있어 `gh pr create`가 안 된다. REST로 연다: `gh api repos/yeons-play/baduk-hansu/pulls --method POST --input pr.json`
- 얕은 복제에서 새 가지를 push하면 "원격 가지 없음" 경고가 날 수 있다. `git config --add remote.origin.fetch '+refs/heads/<가지>:refs/remotes/origin/<가지>'` 후 `git fetch`, `git branch -u origin/<가지>`

### npm 설치가 막힌 작업 환경
- 일부 세션은 npm 레지스트리가 막혀 `npm ci`가 실패한다. 그때는 `bun test`로 대신 검사한다: `node_modules/vitest/index.js`에 `export { describe, it, test, expect, beforeEach, afterEach, beforeAll, afterAll } from 'bun:test';` 흉내 파일을 두면 규칙·강의·AI·저장 테스트가 돈다(무작위 대국·사바키 대조는 PR 자동 검사에서 확인).
- 타입 검사는 전역 `tsc`(주의: `--types ""`는 옵션 오류로 바로 끝나 아무것도 검사하지 않는다. `{"extends":"./tsconfig.json","compilerOptions":{"types":[]},"include":["src"]}` 임시 설정으로 돌리고, `import.meta.env` 오류만 무시), 화면 검사는 `bun build`로 임시 빌드(글꼴 CSS는 빈 흉내 파일) 후 `tests/ui_smoke.py`. 실제 vite 빌드는 배포 단계에서 확인된다.

## 4. 알아 둘 함정

- **CI 시간:** 무작위 대국 1000판이 60초를 넘겨 실패한 적이 있다. `vite.config.ts`의 `testTimeout`을 300초로 늘려 둠
- **화면 클래스 충돌:** 강의 목록 항목은 `.lesson`, 강의 화면은 `.lesson-screen`. 섞으면 레이아웃이 깨진다
- **배포 직후 예전 화면:** GitHub Pages가 최대 10분 캐시한다. 주소 뒤에 `?v=…`를 붙이면 바로 확인 가능
- **카카오톡 안 브라우저:** 홈 화면 설치가 안 되고 저장소가 따로라서 Safari로 열도록 안내. 옮길 때는 설정 → 보호자용 → 백업
- **iOS 소리:** 첫 터치 뒤에만 소리가 난다(`unlockAudio`). 읽어 주기도 터치로 시작된 화면에서만 재생
- **UI 테스트의 AI 무작위성:** 하양이가 무작위로 두므로 특정 자리를 가정하면 가끔 실패한다. 빈 자리를 골라 시도하는 방식 유지. 진짜 바둑 흐름은 집 경계가 다 정해진 판을 저장값으로 넣어 시험한다
- **강의 배치의 차례:** 돌 수로 차례를 정하므로, 까망이가 직접 놓는 단계(`move`·`find`·`legal`)는 엔진에서 흑 차례로, `as: 'w'`는 백 차례로 강제한다
- **사석 규칙(2026-10-20 바뀜):** 둘 다 넘기면 앱이 죽은 돌을 짐작해(`src/engine/ai/dead.ts`, 무작위로 끝까지 두어 보기를 여러 번 해서 대부분 상대 땅이 되는 무리) 흐리게 표시하고, 빼고 센다(`game.score(dead)`·`game.settle(dead)`). 돌을 누르면 무리째 죽은 돌 ↔ 산 돌. 애매한 모양은 짐작이 틀릴 수 있어서 사람이 고치는 게 전제. '더 둘래요'로 되돌릴 수 있다. AI는 여전히 자기 집 안 약한 돌은 잡고 끝내는 편
- **진짜 바둑은 9·13줄:** 덤은 둘 다 7(`docs/rules.md`). 13줄은 AI끼리 두면 150수 안팎으로 9줄의 두 배쯤 걸린다. 19줄은 한 판이 너무 길어 보류. 5·7줄 정규 대국을 넣으려면 덤부터 정해야 한다
- **규칙 설명 주의:** "패스 직후 되따기 불법"은 틀린 설명이었다. 패스는 판을 바꾸지 않아 반복 이력에 들어가지 않는다(`docs/rules.md` 기준)
